如何获取和配置 Token

Get GitHub Token

  1. Visit GitHub Token Settings
  2. Click Generate new token (classic)
  3. Select required permissions (see below)
  4. Set expiration (recommend 90 days)
  5. Generate and copy Token
Token 权限详解（点击展开）
权限 用途 是否必需
public_repo 访问公开仓库 最小权限
repo 访问所有仓库（含私有） 推荐（完整功能）
delete_repo 删除仓库 仅需删除功能时勾选
read:user 读取用户信息 推荐
user:email 读取邮箱地址 可选
推荐配置：
  • 仅浏览/Stats: public_repo + read:user
  • 完整功能: repo + delete_repo + read:user
安全注意事项（重要！）
Token 泄露可能导致：
  • 私有仓库代码被窃取
  • 仓库被恶意删除
  • 被用于挖矿或其他恶意用途
  • 账号安全风险
安全最佳实践：
  1. 最小权限原则 - 只勾选必需的权限
  2. 设置过期时间 - 建议 30-90 天，定期更换
  3. 不要提交到代码库 - 将 Token 放在 .env 文件，并确保 .gitignore 包含 .env
  4. 不要分享截图 - 截图中可能包含 Token
  5. 使用环境变量 - 生产环境使用环境变量注入
  6. 定期检查 - 在 Token 设置页 检查最后使用时间
如果 Token 泄露了：
  1. 立即到 GitHub 设置 删除该 Token
  2. 检查账户是否有异常活动
  3. 生成新的 Token 并更新配置

一键部署到你的 NAS/服务器

适用于: Synology、QNAP、群晖、威联通、Ubuntu、CentOS 等任何支持 Docker 的设备

快速开始 (3 步搞定)

步骤 1: 下载部署文件
cd /volume1/docker # Synology NAS 路径
# 或 cd ~/docker # 其他设备

# 下载配置文件
wget https://raw.githubusercontent.com/your-repo/main/docker-compose.yml
wget https://raw.githubusercontent.com/your-repo/main/nginx.conf
cp .env.example .env

如果你已经在本项目目录中，这些文件已经存在，跳过此步骤。

步骤 2: 配置 GitHub Token

编辑 .env 文件，填入你的 GitHub Token：

GITHUB_TOKEN=ghp_your_token_here
步骤 3: 启动服务
# 启动所有服务
docker-compose up -d

# 查看运行状态
docker-compose ps
部署完成！

服务已在后台运行，现在可以在下方填写你的 NAS 地址了。

免费部署到 Vercel 云平台

优势: 全球 CDN 加速、自动扩展、零维护
劣势: 每月有请求限额、数据经过第三方

重要：部署后必须配置 PAT_1 环境变量

部署完成后，需要在 Vercel 项目中添加 GitHub Token 作为环境变量，否则会显示 "No GitHub API tokens found" 错误。

配置步骤：
  1. 打开 Vercel Dashboard
  2. 选择你刚部署的项目
  3. 进入 Settings → Environment Variables
  4. 添加变量：
    • Name: PAT_1
    • Value: ghp_xxxxxxxxxx（你的 GitHub Token）
  5. 点击 Save
  6. 进入 Deployments → 点击最新部署 → Redeploy
PAT_1 只需要最小权限：
  • public_repo - 只读取公开仓库统计（推荐）
  • 或 read:user - 如果需要显示私有贡献

不需要 repo 或 delete_repo 权限，风险更低

安全提醒：
  • Vercel 环境变量是加密存储的，相对安全
  • 建议为 Stats 服务单独创建一个 Token，与主 Token 分开
  • 设置较短的过期时间（30-90天），定期更换
  • 如有异常，可随时在 GitHub 删除该 Token
