## 最值得迁移的设计经验

### 1. 先建立一个主视觉，再安排内容

参考首屏由大标题、单一主要按钮和持续运转的场景构成。文本区域有局部遮罩，画面主体仍清晰可见；这是有意识的构图。

网站落地：一屏只有一个主要视觉焦点。核心功能卡片应更大，次要工具在较小区域出现；账户状态和辅助链接降低权重。先确定阅读顺序，再画边框和按钮。

### 2. 精致感来自同一套材质与光照逻辑

参考中可以观察到货架、箱体、金属、地面和光束的相互关系。源码还分别处理粗糙度、磨损、湿润程度、法线和反射。

网站落地：少量立体图形使用一致的视角、光源方向、接触阴影和材质。仓库可表现为有厚度的文件夹，主页可表现为精细排版的卡片或窗口。图形应说明功能，避免为填空而加入抽象球体、火箭、星光。

### 3. 页面中的部件必须共享视觉语法

参考的主菜单、分段控件、滑块、任务提示都沿用同一组底色、文字色、强调色、边框和字体规则。

网站落地：先定义字号层级、间距、圆角、阴影和状态色，再应用到全站。图标需有相同的光学尺寸、细节密度和描边规则。品牌 Logo 沿用原稿，不随每次页面调整重画。

### 4. 动效与状态结合

参考中，目标变化、警报、命中、暂停和设置切换有各自的反馈；不同动作不是同一种漂浮动画。设置可以即时生效。

网站落地：悬停表现“可以打开”，按压表现“已经点击”，加载表现“仍在处理”，成功表现“操作完成”。列表与预览更新保持连续。强动效集中于少量视觉入口，数据、文字与操作按钮保持稳定。

### 5. 细节完整，比单个效果强更有价值

参考同时照顾了载入状态、失败展示、设置记忆、键鼠与触控、窄屏及减少动态效果偏好。

网站落地：设计稿包含真实内容密度、空状态、加载状态、长标题、异常提示与移动布局。先用真实浏览器检查全屏组合，再局部微调；不能只以“图标已换了多少个”作为完成标准。

### 6. 视觉效果必须有性能预算

源码存在多个画质档位、分辨率与像素预算、材质复用、几何合并和实例化处理。

网站落地：优先 SVG、CSS、预渲染图。只有需要真实视角交互的少量主视觉才考虑 WebGL。停止不可见的持续动画，支持 `prefers-reduced-motion`，不为几十个列表图标分别创建持续渲染循环。
